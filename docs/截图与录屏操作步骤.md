## 一、截图前准备

### 1. 初始化数据库

在项目根目录打开 PowerShell：

```powershell
Set-Location "C:\Users\21598\Documents\Shangcheng-backend\week4\skill-exchange-platform"
mysql --default-character-set=utf8mb4 -u root -p -e "source ./init_db.sql"
```

输入本机 MySQL 密码。执行后数据库应为 `skill_exchange`，包含 7 张表。

可选检查：

```powershell
mysql -u root -p -D skill_exchange -e "SHOW TABLES;"
```

### 2. 配置 `.env`

```powershell
Copy-Item .env.example .env
notepad .env
```

至少填写：

```dotenv
PORT=3000
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASS=你的MySQL密码
DB_NAME=skill_exchange
JWT_SECRET=请填写一段仅本机使用的长随机字符串
JWT_EXPIRES_IN=8h
NODE_ENV=development
```

`.env` 含数据库密码和 JWT 密钥，不要截图，不要放入 ZIP，也不要提交到 Git。

### 3. 安装依赖并启动

```powershell
npm.cmd ci
npm.cmd start
```

浏览器打开：

```text
http://localhost:3000
```

另开一个 PowerShell 检查服务：

```powershell
Invoke-RestMethod http://localhost:3000/api/health
```

看到 `success: true` 后再开始截图。

## 二、数据库截图顺序

建议使用 MySQL Workbench 或命令行，截图中要能看到数据库名 `skill_exchange`。

### 图 D1：7 张表

```sql
USE skill_exchange;
SHOW TABLES;
```

应看到：

```text
users
skill_categories
skills
exchanges
reviews
notifications
favorites
```

### 图 D2：每表测试数据数量

```sql
SELECT 'users' AS table_name, COUNT(*) AS total FROM users
UNION ALL SELECT 'skill_categories', COUNT(*) FROM skill_categories
UNION ALL SELECT 'skills', COUNT(*) FROM skills
UNION ALL SELECT 'exchanges', COUNT(*) FROM exchanges
UNION ALL SELECT 'reviews', COUNT(*) FROM reviews
UNION ALL SELECT 'notifications', COUNT(*) FROM notifications
UNION ALL SELECT 'favorites', COUNT(*) FROM favorites;
```

每张表应不少于 5 条。截图时不要显示 `password_hash` 的完整内容。

### 图 D3：关联查询

```sql
SELECT s.skill_id, s.title, u.username, c.name AS category_name,
       s.type, s.location_type, s.status
FROM skills s
JOIN users u ON u.user_id = s.user_id
JOIN skill_categories c ON c.category_id = s.category_id
ORDER BY s.skill_id;
```

截图重点：技能、发布者和分类来自三张关联表。

## 四、Apifox 必拍接口步骤

初始化 SQL 已准备演示账号：

```text
账号 A：linxia / 123456
账号 B：zhouyu / 123456
```

建议从干净数据库开始，按以下顺序操作，避免 ID 混乱。

### A02：登录成功并保存 tokenA

- 接口：`POST /api/auth/login`
- Body：

```json
{
  "username": "linxia",
  "password": "123456"
}
```

发送后确认 HTTP 200、`success=true`、返回 `token` 和用户信息。截图时把 Token 中间部分打码，只保留开头和结尾少量字符。

### A03：密码错误

- 接口：`POST /api/auth/login`
- Body 中密码改为 `wrong-password`。
- 应返回 HTTP 401，且仍为 `{ success, data, error, message }` 格式。

### A04：技能分页筛选

- 接口：`GET /api/skills`
- Query：

```text
page=1
limit=5
keyword=摄影
type=offer
locationType=offline
sort=popular
```

截图要同时显示 Query 参数和返回的 `items/pagination`。

### A05：发布技能

- 使用 `tokenA`。
- 接口：`POST /api/skills`
- Body：

```json
{
  "categoryId": 1,
  "type": "offer",
  "title": "Node.js 接口入门演示",
  "description": "讲解 Express 路由、控制器、服务层和统一响应格式。",
  "locationType": "online",
  "coverUrl": null
}
```

发送后记下返回的 `skill_id`，后面称为 `offerSkillId`。

### A06：越权修改

1. 先用账号 B 登录，把返回 Token 保存为 `tokenB`。
2. 使用 `tokenB` 调用 `PUT /api/skills/{offerSkillId}`。
3. Body 只写：

```json
{
  "title": "尝试修改他人技能"
}
```

应返回 HTTP 404 或 403，信息表示技能不存在或无权操作。

### A07：发起交换

1. 切回 `tokenA`。
2. 接口：`POST /api/exchanges`。
3. 账号 A 的 `offerSkillId` 使用 A05 新发布的技能。
4. 目标技能可使用账号 B 的技能 `skill_id=3`（英语口语陪练）。

```json
{
  "offerSkillId": 13,
  "requestSkillId": 3,
  "message": "我可以教 Node.js，希望交换英语口语练习。"
}
```

如果 A05 返回的 ID 不是 13，把 `13` 替换成实际 `skill_id`。发送后记下 `exchange_id`。

### A08：自己申请自己（异常）

- 使用 `tokenA`。
- `requestSkillId` 改为账号 A 自己的 `skill_id=1`。
- 应返回 HTTP 400，错误码为 `SELF_EXCHANGE_NOT_ALLOWED` 或对应中文提示。

### A09：账号 B 接受申请

- 使用 `tokenB`。
- 接口：`PATCH /api/exchanges/{exchange_id}/decision`。

```json
{
  "decision": "accept"
}
```

应返回 `status=accepted`。

### A10：账号 A 第一次确认

- 使用 `tokenA`。
- 接口：`POST /api/exchanges/{exchange_id}/confirm`。
- 应显示申请人已确认、接收人未确认，状态仍为 `accepted`。

### A11：账号 B 第二次确认

- 使用 `tokenB` 调用同一确认接口。
- 应显示双方均确认，`status=completed`，并出现 `completed_at`。

这一张是交换闭环最重要的接口截图。

### A12：完成后评价

- 使用 `tokenA`。
- 接口：`POST /api/reviews`。

```json
{
  "exchangeId": 7,
  "rating": 5,
  "content": "讲解清楚，口语练习过程很有帮助。"
}
```

把 `exchangeId` 替换成 A07 的实际值。首次返回 201；立即重复发送一次，应返回 409，证明不能重复评价。

### A13：收藏幂等

- 使用 `tokenA`。
- 接口：`POST /api/favorites/3`。
- 连续发送两次，均应保持成功且不生成重复记录。
- 再调用 `GET /api/favorites`，确认技能只出现一次。

### A14：通知与统计

依次截图：

1. `GET /api/notifications`：能看到申请、审核、完成或评价通知。
2. `PATCH /api/notifications/read-all`：返回全部已读结果。
3. `GET /api/stats/me`：显示技能、交换、收藏、未读通知和评分统计。
